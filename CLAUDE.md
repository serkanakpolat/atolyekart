# AtölyeKart — Ahşap ve Karakalem Atölyesi

BizCard'a paralel ilerleyen ikinci proje: el yapımı ürün satan bir atölyenin web sitesi.

## Atölye
- **Ad:** Ahşap ve Karakalem Atölyesi
- **Sektör:** El sanatları — ahşap oymacılığı ve resim (karakalem)
- **Ton:** Sıcak, samimi, zanaata saygılı. Abartılı pazarlama dili yok; malzemeyi ve emeği anlat.
- **Dil:** Arayüz ve içerik Türkçe. Fiyatlar Türk lirası (örn. `1.500 ₺`; ahşap 1.500 ₺, karakalem 750 ₺).

## Hedef kitle
- El yapımı, tek ürün (seri üretim olmayan) dekorasyon arayan 28–55 yaş arası kişiler
- Anlamlı hediye arayanlar (düğün, yeni ev, yıl dönümü)
- Özel sipariş (isim/motif oyma, portre resim) isteyen müşteriler

## Ürün kategorileri
- **Ahşap Oyma:** mücevher/hediye kutuları, duvar panoları, kaşık-kepçe, çerçeveler
- **Resim:** karakalem çalışmalar
- **Özel Sipariş:** kişiye özel oyma veya resim

## Ürün veri alanları
`id`, `name`, `category`, `price` (sayı, TL), `description`, `image`, `inStock` (bool)

## Teknik
- Hafta 1: önce düz HTML (`html/index.html`, referans olarak saklanıyor), sonra React'e geçiş.
- Vite + React. Çalıştırma: `npm run dev` → http://localhost:5173
- Yapı: ürün verisi `src/data/products.js`; bileşenler `src/components/` (ProductList → ProductCard → ProductImage); stiller `src/index.css`.
- Ürün görselleri `public/urunresimleri/` içinde, kodda `/urunresimleri/...` yoluyla.
- Seçili ürün + açık form durumu `App.jsx`'te (`activeForm`); `onOrder`/`onNotify` App → ProductList → ProductCard prop'larla iner. Formlar `FormDialog` (native `<dialog>`) içinde: `OrderForm`, `StockNotifyForm`.
- Yayın: GitHub Pages → https://serkanakpolat.github.io/atolyekart/ (repo: serkanakpolat/atolyekart). `npm run deploy` yerelde build alıp `gh-pages` dalına gönderir; `.env.local` build'e gömülür. Build'de Vite `base` = `/atolyekart/`, görseller `import.meta.env.BASE_URL` ile çözülür.
- Webhook: payload kurucuları ve gönderim `src/lib/webhook.js`'te. İstemci önce `/api/token`'dan sunucu imzalı JWT alır, sonra `/api/webhook`'a POST eder (Vercel fonksiyonları `api/`; yerelde `vite.config.js` aynı handler'ları middleware olarak bağlar). Sır `JWT_SECRET` yalnızca sunucuda (`.env.local` ve Vercel env; `VITE_` öneki yok). Harici webhook servisi yok; gelen istekler yerelde terminalde ve `GET /api/webhook`'ta, canlıda Vercel Logs'ta görünür. `productId`/`productName` ürünün `id`/`name` alanından gelir.
- n8n (Hafta 3): `api/webhook.js` doğrulanmış `order_created` isteklerini (jwt hariç) `N8N_WEBHOOK_URL`'e iletir; adres yalnızca sunucuda (`.env.local` / Vercel env), path tahmin edilemez olduğu için gizli tutulur. Akış n8n Cloud'da (ryazici.app.n8n.cloud, workflow "AtölyeKart — Sipariş → Sheet + AI Teşekkür Maili"): Webhook → Sheet'e sipariş satırı ("AtölyeKart Siparişler" e-tablosu) → Gemini (`gemini-3.5-flash`) ile teşekkür + tahmini süre maili → aynı satıra yazma. Mail gönderilmez, yalnızca taslak. Yerel Docker n8n bu projede kullanılmaz.
- n8n (Hafta 4): `stock_notification_requested` istekleri `N8N_STOCK_WEBHOOK_URL`'e gider (yine yalnızca sunucuda). n8n ürün bilgisini `GET /api/products`'tan okur (`src/data/products.js`'in görselsiz kopyası). Akışlar: "Ortak Doğrulama (Sub-workflow)" (e-posta biçimi + ürün ID katalog kontrolü, geçersizse Stop and Error) — sipariş ve stok akışlarının ikisi de çağırır; "Hata Yakalayıcı (Error Handler)" iki ana akışın Error Workflow'u, hataları Sheet'in "Hatalar" sekmesine yazar; "Stok Bildirimi → AI Alternatif Öneri" (AI Agent + `urun_katalogu` HTTP aracı → "Stok Talepleri"); "Günlük Sipariş Özeti" (her gün 21:00, Code ile ürüne göre gruplama → Merge ile katalog → Loop → "Günlük Özet"). n8n 2.x'te kaydetmek yetmez, akış yayınlanmalı (Publish). Google Sheets append node'larında "Minimise API Calls" (`useAppend`) açık kalmalı; kapalıyken eşzamanlı execution'lar aynı satırın üstüne yazıyor.
- n8n (Soru Sor): sayfadaki `AskQuestion` bölümü `question_asked` gönderir; `api/webhook.js` bunu `N8N_ASK_WEBHOOK_URL`'e iletip yanıtı **bekler** (60 sn) ve `{ ok, answer }` döner. Token'da productId boş. `sessionId` ziyaretçi başına sabit: `localStorage`'da (`atolyekart_ziyaretci`), görünen yazışma da (`atolyekart_sohbet`, son 20) orada; 30 günden eskisi açılışta silinir, "Yeni sohbet" butonu ikisini sıfırlar. localStorage erişimi try/catch içinde (gizli pencerede hata verebilir). Akış "AtölyeKart — Soru Sor → AI Agent": Webhook (Respond: using Respond to Webhook node) → Execution Data (soru/oturum) + Ürün Kataloğunu Al → AI Agent (katalog system prompt'ta) → Respond to Webhook `{ answer }`. Sohbet hafızası **Redis Chat Memory** (Upstash Redis, n8n kimlik bilgisi "Upstash Redis"): anahtar `atolyekart:sohbet:<sessionId>`, son 10 etkileşim, TTL 30 gün. Hata yönetimi: "Ürün Kataloğunu Al" 3 deneme (5 sn zaman aşımı), Agent 2 deneme; yine başarısızsa hata çıkışından 200 + kibar özür `{ answer }` döner ve hata Sheet'in "Hatalar" sekmesine yazılır (bu kolda execution başarılı sayılır, Error Workflow tetiklenmez). n8n'e hiç ulaşılamazsa `api/webhook.js` 502 döner, site "Şu an yanıt veremedim…" gösterir. Katalog araç (tool) yerine prompt'ta: Gemini döneminde araç çağrısı yanıtı 30–60 sn'ye çıkarıyordu.
- n8n (RAG): Soru Sor Agent'ının modeli artık Claude Haiku 5.5 (`claude-haiku-5-5`, adaptive thinking effort `low`, maxTokens 8192; Haiku 5.5 varsayılan dışı temperature'ı reddeder, ayarlama). Bilgi bankası: "AtölyeKart — Bilgi Bankası Yükleme (RAG)" akışı (n8n Form ile .txt ya da .pdf yüklenir → PDF'in metni ve metadata'sı Extract from File ile okunur → numaralı "N - Başlık" bölümlerine ayrılır → Gemini `gemini-embedding-001` → Simple Vector Store `atolyekart_<kategori>`). Kategori: .txt → `sss`; PDF → metadata'daki özel `/Kategori` alanı ya da Keywords'teki `kategori=...` (`sss`, `ozel_siparis`). Her yükleme yalnızca kendi kategorisinin eski içeriğini siler. Yeni kategori eklemek için yükleme kodundaki `KATEGORILER` listesine ve Soru Sor akışına yeni bir araç eklenmeli. Soru Sor Agent'ı iki aracı kullanır (retrieve-as-tool, topK 4): "SSS Bilgi Bankası" (`atolyekart_sss`) ve "Özel Sipariş Rehberi" (`atolyekart_ozel_siparis`, kaynağı repo kökündeki `Ozel-Siparis-Rehberi.pdf`; içeriği örnek/kurgu). Sorgu embedding modeli yükleme akışıyla aynı olmalı. Anthropic'in embedding API'si yok, bu yüzden embedding Gemini. Simple Vector Store n8n belleğinde: n8n yeniden başlarsa `SSS.txt` ve `Ozel-Siparis-Rehberi.pdf`'i formdan tekrar yükle.
- n8n (Supabase RAG): Simple Vector Store akışlarının birebir Supabase kopyaları — "AtölyeKart — Bilgi Bankası Yükleme (Supabase RAG)" (form adresi n8n'de, akışın tetikleyicisinde; herkese açık olduğundan repoya yazılmaz) ve "AtölyeKart — Soru Sor → AI Agent (Supabase RAG)" (webhook yolu da gizli, repoya yazılmaz; 27.11.2026'dan beri site bu bota bağlı — Vercel ve `.env.local`'da `N8N_ASK_WEBHOOK_URL`. Eski Simple Vector Store botu yayında ama siteden çağrılmıyor; geri dönmek için aynı değişken eski adrese çevrilip yeniden yayınlanır). Tek tablo `atolyekart_belgeler` (pgvector 3072 boyut, arama fonksiyonu `match_atolyekart_belgeler`, kurulum `supabase/atolyekart_belgeler.sql`); kategori `metadata.kategori`'de, iki araç bu alana göre filtreler. Yükleme önce yeni parçaları yazar, sonra aynı kategoride `yukleme_id`'si farklı eski parçaları siler. n8n kimlik bilgisi "Supabase account 3" (service_role/secret anahtar; yalnızca n8n'de). Tablo SQL ile açıldığı için service_role'e GRANT gerekir (dosyada var); yoksa 403 "permission denied for table". Veri kalıcı: n8n yeniden başlasa da tekrar yükleme gerekmez.
- n8n (Hafta 6): MCP — Claude Code'a bağlı n8n instance MCP sunucusu kullanılır (akışlarda "Available in MCP" açık): `search_workflows`, `execute_workflow`, `get_workflow_execution`, `search_workflow_executions` ile akış çalıştırma ve execution sorgulama. n8n API — `npm run n8n:haftalik` (`scripts/n8n-haftalik-siparis.mjs`) sipariş akışının bu haftaki (pazartesi 00:00 TR) execution'larını `GET /api/v1/executions` ile sayar: başarılı webhook execution = sipariş. Anahtar `.env.local`'da `N8N_API_KEY` (yalnızca yerel; `VITE_` öneki yok, Vercel'e eklenmez). Kanıtlar `docs/hafta6-kanit/`.
- Yayın asıl adresi Vercel: https://atolyekart-rose.vercel.app (GitHub Pages'te backend olmadığı için formlar çalışmaz).
- Renkler BizCard'ın sarı/siyah paletinden (`Bizcard v1/tokens.css`), `src/index.css` başındaki değişkenlerde. Koda sabit renk yazma, değişken kullan. Sarı (`--primary`) yalnızca dolgu; üstündeki yazı `--on-primary` (siyah). Koyu tema `prefers-color-scheme` ile.
- Webhook payload sözleşmesi (alan adları değiştirilmez):
  - Sipariş: `event, name, productId, productName, phone, email, quantity, source`
  - Stok bildirimi: `event, name, productId, productName, email, source`
  - Soru: `event: "question_asked", question (3–500 karakter), sessionId (ziyaretçi başına sabit), source`
